2023
JavaSeleniumRobot FrameworkJenkins

Test automation for a newly acquired trading platform

Problem
The platform had only manual testing. A full regression took over three months, so feedback on every change was slow.
Decision
The UI and backend were tightly coupled over WebSockets, so I tested through real user flows: Java Selenium keywords for Robot Framework, mocked markets, and a CI defined entirely as code with Jenkins Job DSL so it could be rebuilt from scratch.
Result
The team grew my first four tests into ~900. Full regression now runs in 4–6 hours on one machine, and manual regression is gone.

Learned The most useful thing I built was a foundation other people could keep extending.

2024
Docker SwarmPrometheusGrafanaNode.js

Load testing to a contractual target, from nothing

Problem
A client contract expected around 200 concurrent users. The product had never been performance tested.
Decision
The server couldn't be loaded directly at the API, so I reused the acceptance-test user flows to simulate many users. One machine fell over at about 50, so I spread containers across spot machines with Docker Swarm and instrumented the code with Prometheus and Grafana, all behind a one-click Jenkins job with warm-up and burst phases.
Result
Validated 200+ users, found a WebSocket bottleneck in the Node.js tier, and prototyped horizontal scaling as the fix.

Learned When the obvious tool doesn't fit, the harness you already have often does.

2023 – 2024
FIXIntegrationGUI

Joining a front-office platform to a legacy back office

Problem
A high-visibility client project with tight deadlines: embed our trading GUI in the client's portal and send trades downstream to a legacy system. The two systems disagreed on whether a user could act on behalf of other organisations.
Decision
With a senior engineer, I designed a parent/child user model with in-portal user switching, and integrated downstream over FIX. I also clarified requirements with Product and set up the standard release-request process.
Result
The design is still in production. I became the go-to engineer for the integration and handed it over to Customer Support.

Learned A clean model on paper loses to one both systems can live with.

2024 – 2025
Azure AD B2CGraph APINode.jsAWS

Multi-factor authentication for every client

Problem
A company-wide mandate to enforce MFA. I inherited an early proof of concept and owned the rest: breakdown, build and client rollout. Users with several accounts blocked the design before any MFA work could ship.
Decision
I wrote up the options and got stakeholder sign-off on a fix for each kind of multi-account user. For the rollout I stood up parallel instances of the shared service instead of upgrading it, and switched MFA on per client through configuration, so any client could be rolled back on its own. I built a Graph API tool to migrate users into Azure.
Result
11 clients, tens of thousands of users, 0 rollbacks. Ours was the first product at ION to finish, and other teams reused the approach.

Learned A one-sprint estimate usually means the hard part hasn't been found yet.

2025
Incident responseVulnerability management

A security incident, and the process it led to

Problem
As the product's security officer, I joined a weekend production security incident on the application side.
Decision
I reproduced the exploit in a test environment, which pinned down the root cause, and we shipped a fix and runtime upgrade to every client deployment before the next business day. Afterwards I built a division-wide vulnerability dashboard and wrote remediation workflows with SLAs, so we would act on findings instead of only reading reports.
Result
The workflows were presented at a CEO session and adopted across the division and by other divisions.

Learned Visibility without a process just makes the backlog easier to see.
